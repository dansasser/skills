# Operator-neutral project opt-in

Copy the rule below into a project's applicable agent-instruction file when the project intentionally adopts Graph Development. Do not place machine-specific paths or personal standing authority in the public rule.

## Rule

This project explicitly opts this project into `$graph-development` for governed software-lifecycle mutations. Load the skill before project mutation and use the codebase Development Lifecycle Graph as durable lifecycle state.

The user's approved outcome and acceptance contract are the scope ceiling for the current run. Recording a graph mutation never promotes its nodes, expands the current projection, or makes backlog mandatory. Promote work only when it maps to an existing approved requirement, current regression, or acceptance gap and remains within the approved outcome. An outcome change requires separate explicit authority and the successor-run path.

After bounded graph recording or validation, return to the requested critical path. Ready, invalidated, deferred, or newly recorded work outside the current projection remains durable backlog. That backlog cannot block current-run completion.

Do not create a parallel TLG, PLG, DLG, plan, or governance workflow. Other skills may perform bounded work inside the current run but do not replace the DLG.
